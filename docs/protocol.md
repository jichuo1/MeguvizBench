# 评测与评分协议 1.0

## 评分粒度

每个试次以 100 分为满分。TaskSpec 的 rubric 逐项固定 ID、分值、证据、方法、类别、失败说明。独立行为分别占分，同一行为的多组样本汇入同一条目。以区间修复为例，单点、边界相邻、重叠和输入兼容分别验收。新增等价样本只提高检查强度。有效回归或新能力的权重调整需要升级评分器版本。

评分器为每项返回通过、失败或缺测。通过获得固定分值，失败得 0，缺测保留空值，整题转为待复核。正确性、回归或约束未通过时，性能项被门槛拦截。核心正确性、证书合法性和模型闭合可激活封顶，多个封顶同时触发时取最小值。证据记录保留原始分、已测分值、所有触发的封顶及最终分。分项证据包含可观察目标、检查方法、通过状态、分值和失败原因。行为验收另记录输入、输出摘要以及受限的私有日志预览。

SVG 样例分别核对 XML、可访问名称、组件结构、几何与前景关系。OBJ 样例分别核对格式、三角形、闭合、朝向、几何和尺寸。当前视觉检查来自几何条件。像素渲染、审美量表和 Blender 实际导入未测。后续人工量表应事先冻结分档和锚点样例，由独立评审双判，分歧进入复核。

## 冻结、重复、失败

- TaskSpec 由严格 Python 校验器检查。RunSpec 固定任务包和评分器内容、控制器代码摘要、模型与 Agent 配置、试次额度、工具和环境条件。TrialResult 记录试次/尝试 ID、证据索引、提交摘要、来源、分项成绩、耗时、状态和使用量。PublicResult 使用独立的严格字段允许列表。
- 一个任务只计入一个主维度。多个配置共享每个任务和重复编号对应的种子。种子标识试次，当前单轮模型接口没有发送供应商采样种子。每个候选使用新目录，每个黑盒用例使用新进程或新容器。需要保留状态的测试将整段操作序列作为一次用例。
- 成绩为 100 标记 `passed`，候选未完成或未通过标记 `model_error` 并保留已得分。预算耗尽和协议内超时计作试次失败。环境、服务或评分器故障、取消、配置不兼容、缺测和人工复核保留独立状态。工作流被强制终止时，未落盘试次显示缺测，保留已归档的尝试。
- 只有 HTTP 429、502、503、504 可重试一次。原尝试和费用保留，试次成绩取最后一次有效记录。连接中断和结果不确定的请求不自动重放。付费运行使用归档内的批次及试次一次性领取键。使用过的运行键不能再次派发。
- 统计先平均重复，再平均变体，最后对家族等权。缺测维度保持 N/A。三家族起计算 95% 家族聚类 bootstrap 区间，区间反映有限家族的抽样波动。八个维度均达到三家族且批次完整时才计算综合分，只有同一比较条件的完整正式记录进入排名。

## 预算与用量

公开检查的调用上限和美元额度均为 0。手动运行选择固定正预算。每个试次的额度取单题上限与总额度等分的较小值。默认档 `pilot` 总额 USD 6.00，单试次最多 USD 0.25，最多两次请求、每请求最多 4096 输出 token，试次目标时限 240 秒。托管矩阵最多两个试次并行。通过可信调用端在每次请求前用请求字节数、协议余量、最大输出和保守费率估算并预留金额。供应商用量返回后记录成本估计，未知用量记 null。估计会受计费、缓存费率和在途请求影响。请求预留文件先于发送落盘；请求后中断时恢复为未知费用并保留缺测。供应商项目账单为最终结算依据。

当前用 OpenAI Chat Completions 传输，以单轮 JSON 文件提交 Agent 运行。只向模型提供题面、提交路径和允许公开的起始文本。模型接入路径的凭据由控制侧持有。价格依据和核对日期见 [模型配置](../configs/presets.json)。配置中的模型名称是供应商公开模型 ID，版本追踪同时保留实际返回的模型标识，供应商侧别名更新仍可能影响复现。[Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/methods/create) · [Luna 计费](https://developers.openai.com/api/docs/models/gpt-5.6-luna) · [Terra 计费](https://developers.openai.com/api/docs/models/gpt-5.6-terra)

## 隔离与证据

Linux 执行器只把经过路径、数量、文本类型和大小校验的候选文件目录，以只读方式挂给非 root 容器。禁用外网、额外权限和 Docker socket，限制内存、进程、临时空间、时间和输出。行为验收按单次 JSON 输入调用候选，预期结果、评分规则及计算在控制侧。SVG、OBJ、证书由受信解析器作为数据读取。受信评分脚本必须随维护者审核过的任务快照部署。Docker 仍共享宿主机内核，部署前应实测本协议的隔离探针。当前正式路径限定有限大小的 UTF-8 文本产物。Android、浏览器工具操作、桌面、GPU、真机和真实性能基准仍待接入。

付费工作流使用受保护环境，归档仓库为独立私有仓库。每个对象带内容摘要，写入仅允许创建；恢复后校验包、计划、来源、评分器和提交文件摘要。发布先按已知字段构建公开汇总，再递归验证结构。候选 SVG、HTML、日志及正文不会作为页面资源发布。合成泄露标记测试覆盖汇总投影与站点产物。公共缓存不保存私有材料。

`rescore` 用原冻结版本重算并比对已保存观察和分项结果。保留原框架 checkout 和题包快照可复现原评分器。若要按新版评分器复验同一提交，使用 `regrade` 指定审核过的新任务包和评分器版本，按原 Docker 环境执行，将结果写入新文件。新评分记录不替换原运行证据。

```text
python -m meguvizbench rescore --plan PLAN --trial-id TRIAL --evidence ATTEMPT --output RESCORE
python -m meguvizbench regrade --plan PLAN --trial-id TRIAL --evidence ATTEMPT --scorers NEW_TASK_ROOT --scorer-version VERSION --output REGRADE
```

对私有运行，两条命令另需 `--private-tasks ORIGINAL_TASK_ROOT`。可用 `archived-plan --run-id RUN --output PLAN` 取回原清单，再用 `restore --plan PLAN --output DEST` 恢复证据。私有运行同样指定原任务根目录。对未知 API 结果或归档写入失败，先恢复已落盘记录，核对提供商账单与请求记录，保留原运行键，勿直接重放。
